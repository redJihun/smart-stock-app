## 1. 제품 개요 (Product Overview)

### 1.1 비전

**"감이 아닌 데이터로, 수동이 아닌 자동으로."**

Smart Stock은 정량적 데이터 기반의 알고리즘 트레이딩 시스템이다.
모든 투자 시그널과 그 결과를 기록하고, 객관적 성과 데이터가 사전에 정한 기준(Go-Live Gate)을 충족할 때에만 실전 자본을 투입한다.

### 1.2 미션

개인 개발자 또는 소규모 팀(2~6명)이 **기관급 트레이딩 인프라**를 최소 비용(월 $20 이내)으로 구축하고 운영할 수 있게 한다.

### 1.3 핵심 가치 제안 (Value Proposition)

| # | 가치 | 설명 |
|---|------|------|
| 1 | **정량적 의사결정** | 모든 시그널과 결과를 기록하여 전략의 실제 성과를 객관적으로 평가한다. "이 전략이 실제로 돈을 벌었는가?"에 데이터로 답한다. |
| 2 | **단계적 자동화** | 의사결정 보조 → 자동시뮬레이션(자동 주문을 가정하고 실시간 장에서 시뮬레이션) → 반자동(알림+수동 주문) → 완전 자동(자동 주문+리스크 관리)으로 리스크를 점진적으로 관리하며 전환한다. |
| 3 | **글로벌 시장 대응** | 한국(KOSPI/KOSDAQ)을 우선 지원하고, 동일 프레임워크로 미국 및 글로벌 시장으로 확장한다. |

### 1.4 Go-Live Gate

이 프로젝트의 핵심 안전장치. 페이퍼 트레이딩 단계에서 아래 **정량 기준을 모두 충족**해야만 실전 자본을 투입한다.

| 지표 | 최소 기준 | 측정 기간 |
|------|----------|----------|
| 페이퍼 트레이딩 기간 | 3개월 이상 | — |
| 시그널 수 | 500건 이상 | 전체 |
| 적중률 (방향) | 55% 이상 | 최근 90일 |
| 샤프비율 (Sharpe Ratio) | 1.0 이상 | 최근 90일 |
| 최대낙폭 (MDD) | -15% 이내 | 최근 90일 |
| 수익 팩터 (Profit Factor) | 1.3 이상 | 최근 90일 |
| 시스템 가동률 | 99% 이상 | 최근 30일 |

> Go-Live 기준은 실제 데이터가 쌓이면서 점진적으로 보정한다.
> 처음부터 완벽한 기준을 정하는 것보다, **기록하고 관찰하는 것**이 중요하다.

## 2. 문제 정의 (Problem Statement)

개인 투자자와 소규모 트레이딩 팀이 알고리즘 기반 투자를 시도할 때 직면하는 핵심 문제 4가지를 해결한다.

### 2.1 전략 검증의 부재

**문제**: 대부분의 개인 트레이더는 백테스트 없이 전략을 실전에 투입하거나, 과적합(overfitting)된 백테스트 결과를 신뢰한다. look-ahead bias, survivorship bias 같은 함정을 인지하지 못한다.

**Smart Stock의 접근**: `BacktestEngine`이 `signals.shift(1)`로 look-ahead bias를 원천 차단한다. 미청산 포지션은 마지막 종가로 강제 청산하여 생존 편향을 방지한다. 4개 핵심 성과 지표(수익률, MDD, 샤프비율, 승률)를 자동 산출하여 전략의 실제 성과를 객관적으로 보여준다.

### 2.2 성과 추적 시스템의 부재

**문제**: 과거 매매 시그널의 성과를 체계적으로 기록하지 않아, "이 전략이 최근 3개월간 실제로 얼마나 벌었는가?"에 답할 수 없다. 결국 감각적 판단에 의존하게 된다.

**Smart Stock의 접근**: `SignalLogger`가 모든 매수/매도 시그널을 Parquet 파일에 불변(append-only)으로 기록한다. `OutcomeTracker`가 각 시그널 이후 1일/1주 수익률을 자동 추적한다. `run_and_track()` 파이프라인이 백테스트 실행과 시그널 기록을 하나의 호출로 처리한다.

### 2.3 인프라 진입장벽

**문제**: 기관은 Bloomberg Terminal, 자체 API 인프라, 전담 퀀트 팀을 보유하지만, 개인/소규모 팀은 이를 구축할 자본과 인력이 없다. QuantConnect 등 유료 플랫폼은 월 비용이 높거나 커스터마이징에 제약이 있다.

**Smart Stock의 접근**: Python 오픈소스 생태계(pandas, pyarrow 등)와 무료 데이터 소스(FinanceDataReader, yfinance)를 기반으로, 월 $20 이내 비용으로 서버 기반 트레이딩 인프라를 구축한다. Docker 기반 배포로 재현성과 이식성을 확보한다.

### 2.4 글로벌 시장 데이터의 분절

**문제**: 한국과 해외 시장의 데이터 소스가 다르고(fdr vs yfinance), API 인터페이스도 다르다. 통합된 추상화 계층 없이는 멀티마켓 전략 개발이 번거롭다.

**Smart Stock의 접근**: `fetch_stock(ticker, market)` 단일 인터페이스가 내부적으로 Market(KRX/NYSE/NASDAQ 등)에 따라 적절한 데이터 소스를 선택한다. `BaseStrategy` ABC를 상속하면 어떤 시장의 데이터든 동일한 방식으로 전략을 적용할 수 있다.

## 3. 목표 및 성공 지표 (Goals & Success Metrics)

### 3.1 Phase별 비즈니스 목표

| Phase | 비즈니스 목표 | 핵심 KPI | 측정 방법 |
|-------|-------------|---------|----------|
| 0 ✅ | 전략 개발 + 백테스트 + 추적 기반 구축 | 4개 전략 구현, 104개 테스트 통과 | pytest |
| 1 | 기술적 분석 역량 고도화 | 10개+ 기술 지표, 분봉 데이터 수집 정상 가동 | 코드 + 노트북 |
| 2 | 실시간 전략 검증 체계 수립 | 페이퍼 트레이딩 24/7 운영, 일간 리포트 자동 생성 | 시스템 가동률 |
| 3 | 투자 판단 정보원 다양화 | 3개+ 대안 데이터 소스 연동 | 데이터 파이프라인 |
| 4 | ML 기반 예측 모델 검증 | ML 전략의 백테스트 샤프비율 ≥ 룰 기반 대비 +0.2 | tracking 데이터 |
| 5 | 비정형 데이터 활용 체계 구축 | 뉴스 감성→시그널 파이프라인 가동 | 파이프라인 |
| 6 | **실전 자본 투입** | Go-Live Gate 전 항목 충족 + 실전 1건 이상 체결 | Go-Live 체크리스트 |

### 3.2 시스템 수준 KPI

| 지표 | 기준 | 적용 시점 |
|------|------|----------|
| 서버 가동률 | 99% 이상 (장중 시간대) | Phase 2~ |
| 분봉 데이터 수집 지연 | 5분 이내 | Phase 1~ |
| 시그널 생성 지연 | 데이터 입수 후 10초 이내 | Phase 1~ |
| 일봉 백테스트 (5년, 단일 전략) | 5초 이내 | Phase 0~ |
| 월 운영 비용 | $20 이내 (서버+데이터+API) | 전 Phase |

### 3.3 Go-Live Gate

섹션 1.4에서 정의한 기준을 공식 KPI로 채택한다. 기준 충족 여부는 `OutcomeTracker`의 축적 데이터로 자동 판정하며, Phase 6에서 Go-Live Gate 자동 판단 기능(FR-605)으로 구현한다.

## 4. 대상 사용자 (Target Users)

### 4.1 현재 상태 → 목표 상태

| 시점 | 팀 규모 | 구성 |
|------|--------|------|
| **현재** (Phase 0~1) | 1인 | 개발자 겸 트레이더 겸 분석가 (모든 역할 겸임) |
| **목표** (Phase 2~6) | 2~6명 | 역할 분화 (아래 페르소나 참조) |

### 4.2 사용자 페르소나

#### 페르소나 A: 퀀트 개발자

- **프로필**: Python 중급 이상, 통계/금융 기본 지식
- **핵심 니즈**: 전략 아이디어를 빠르게 코드로 구현하고 백테스트로 검증
- **주요 워크플로우**: `BaseStrategy` 상속 → 전략 구현 → `BacktestEngine.run()` → 결과 분석 → 파라미터 최적화
- **사용 환경**: 서버 SSH + Jupyter 노트북 + CLI

#### 페르소나 B: 데이 트레이더

- **프로필**: 시장 감각은 있지만 코딩 경험 제한적
- **핵심 니즈**: 전략 시그널을 실시간으로 받고, 성과 리포트를 확인
- **주요 워크플로우**: 알림 수신(Slack/Telegram) → 대시보드에서 시그널 확인 → 반자동 주문 결정
- **사용 환경**: 웹 대시보드 + 모바일 알림

#### 페르소나 C: 데이터 분석가

- **프로필**: 데이터 분석/ML 전문, 금융 도메인 학습 중
- **핵심 니즈**: 대안 데이터 수집/분석, 피처 엔지니어링, 모델 학습 및 평가
- **주요 워크플로우**: 데이터 파이프라인 구축 → 피처 스토어 관리 → ML 실험 → 성과 비교
- **사용 환경**: Jupyter + MLflow + CLI

#### 페르소나 D: UI/UX 개발자

- **프로필**: 직관적인 UI와 사용자 경험을 중시하는 UX 디자인 전문, 금융 도메인 학습 중
- **핵심 니즈**: 데이터 분석가의 분석 결과 및 핵심 KPI를 데이 트레이더(페르소나 B)에게 웹 UI 대시보드 형태로 제공. UI 상에서 모의 거래 기능 지원 (추후 브로커 API 연동으로 실거래 전환 가능)
- **주요 워크플로우**: 성과 비교 결과 확인 → 직관적인 시각화 대시보드 구현 → 모의 거래 UI 구현 → 사용자 피드백 반영
- **사용 환경**: Streamlit/Gradio + Jupyter (프로토타이핑) + CLI + 서버 SSH

### 4.3 팀 규모별 역할 분담

| 역할 | 1명 (현재) | 2명 | 6명 |
|------|-----------|-----|-----|

### 7.3 핵심 설계 원칙

1. **전략 확장성**: `BaseStrategy` ABC 패턴 유지 — 새 전략은 상속만으로 추가
2. **데이터 소스 추상화**: `fetch_stock` 인터페이스 뒤에 fdr/yfinance/브로커 API를 감춤
3. **불변 기록**: Parquet append-only 로깅 — 모든 시그널/결과를 불변 로그로 보존
4. **의존성 주입**: `OutcomeTracker(fetcher=...)`, `run_and_track(engine=..., logger=...)` 패턴
5. **관심사 분리**: 데이터 수집 / 전략 / 백테스트 / 추적이 독립 모듈로 존재

### 7.4 데이터 흐름 (종단간)

```
데이터 수집 → 지표 계산 → 시그널 생성 → 백테스트 or 실시간 실행
                                              │
                                    ┌─────────┴──────────┐
                                    │                    │
                              주문 실행            가상 주문 (페이퍼)
                                    │                    │
                                    └─────────┬──────────┘
                                              │
                                    결과 추적 (OutcomeTracker)
                                              │
                                    성과 분석 + Go-Live Gate 판정
                                              │
                                    피드백 → 전략 개선 / ML 재학습
```

- **시장 우선순위**: 한국 시장 먼저 구현 후 글로벌 확장
- **투자 자본**: 시스템에 하드코딩하지 않고, 설정 가능한 파라미터로 설계

## 11. 부록 (Appendix)

### A. 용어집 (Glossary)

| 용어 | 설명 |
|------|------|
| **Go-Live Gate** | 실전 자본 투입 전 충족해야 하는 정량적 기준 체크리스트 |
| **샤프비율** (Sharpe Ratio) | 위험 대비 수익률 지표. (수익률 - 무위험수익률) / 수익률 표준편차 |
| **MDD** (Maximum Drawdown) | 최대낙폭. 고점 대비 최대 하락 폭 |
| **슬리피지** (Slippage) | 주문가와 실제 체결가의 차이 |
| **포지션 사이징** (Position Sizing) | 한 거래에 투입할 자본 비율 결정 방법 |
| **Kelly Criterion** | 최적 베팅 비율을 수학적으로 계산하는 공식 |
| **look-ahead bias** | 미래 데이터를 현재 시점 의사결정에 사용하는 오류 |
| **walk-forward CV** | 시계열 데이터에 적합한 교차검증 방법. 과거→미래 방향으로만 검증 |
| **페이퍼 트레이딩** | 실제 자본 없이 가상으로 매매를 시뮬레이션하는 방식 |
| **레짐** (Regime) | 시장의 거시적 상태 (강세/약세/횡보/고변동 등) |
| **드리프트** (Drift) | ML 모델의 예측 성능이 시간이 지남에 따라 저하되는 현상 |
| **피처 스토어** (Feature Store) | ML 피처를 중앙 관리하는 저장소. 재현성과 재사용성 보장 |
