# ADR-0004: 노트북 도구 Jupyter 선택

|------|------|

## 맥락 (Context)

탐색적 데이터 분석(EDA)과 전략 실험을 위한 노트북 도구를 선택해야 한다.
주요 후보는 **Jupyter Notebook**과 **Marimo**이다.

| 항목 | Jupyter Notebook | Marimo |
|------|-----------------|--------|
| 자료·예제 | 매우 풍부 | 적음 (신생) |
| Git 친화성 | 낮음 (JSON 포맷) | 높음 (`.py` 파일) |
| 실행 방식 | 수동 셀 실행, 숨겨진 상태 존재 | 리액티브 (의존 셀 자동 재실행) |
| 커뮤니티 | 업계 표준 | 성장 중 |
| 학습 곡선 | 낮음 | 중간 |
| 적합 용도 | 탐색·실험 | 재현 가능한 파이프라인 |

## 결정 (Decision)

**Jupyter Notebook을 메인 노트북 도구로 채택**한다.

현재 프로젝트는 탐색적 분석 단계이며, 레퍼런스·예제가 압도적으로 많은 Jupyter가 초기 생산성에 유리하다.
Marimo는 전략 코드가 안정화된 이후, 재현 가능한 파이프라인이 필요한 시점에 선택적으로 도입을 검토한다.

### 참고자료 (References)

- [Jupyter 공식 문서](https://jupyter.org/)
- [Marimo 공식 문서](https://marimo.io/)

## 결과 (Consequences)

### 이점 (Benefits)

- 국내외 주식 분석 예제의 대부분이 Jupyter 기반 — 레퍼런스 그대로 활용 가능
- 셀 단위 실행으로 빠른 탐색·실험 가능
- 이미 익숙한 도구 — 학습 부담 없음

### 단점 (Drawbacks)

- `.ipynb`는 JSON 포맷이라 git diff가 읽기 어렵고 충돌 해소가 번거롭다
- 숨겨진 상태(hidden state) 문제 — 셀 실행 순서에 따라 결과가 달라질 수 있다

### 리스크 (Risks)

- 노트북이 복잡해지면 재현성 문제가 생길 수 있다 — 탐색 완료 후 핵심 로직은 `src/` 모듈로 옮기는 원칙을 지켜야 한다

## 부록 (Appendix)

### 노트북 관리 원칙

- `notebooks/` 아래 파일명은 `kebab-case.ipynb`
- 탐색이 완료된 로직은 `src/smart_stock/` 모듈로 이동
- 노트북 내 데이터 파일 경로는 `data/raw/` 또는 `data/processed/` 기준으로 작성
